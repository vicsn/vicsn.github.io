Varuna vs Marlin: where batching changes the soundness argument

Marlin's AHP has one soundness argument: a wrong witness leaves some residual polynomial nonzero, and a random challenge exposes it except with probability deg/|S|. Varuna proves many circuits and instances in one proof by combining their claims with transcript weights before any check runs. That adds a second way to fool the verifier, and new obligations on domains, on transcript order, on the weights fixed to 1, and on how the statement is encoded.

Proven, one drawn element at a time

Claims are combined before they are checked

Marlin

Each identity is tested on its own. A wrong witness leaves some residual polynomial nonzero, and a random challenge exposes it except with probability deg/|S|.

Varuna

Per-circuit and per-instance claims are multiplied by transcript weights and summed first: ν_i and τ_{i,j} in the rowcheck, μ_i, ρ_{i,j} and η_M in lineval, δ_{M,i} in the matrix sumcheck. The first weight of each family is 1.

Why soundness cares

A false claim can hide behind weights that make the sum vanish. Every point check then passes, so Schwartz–Zippel alone does not catch it.

What Lean proves

inspectBatch returns the weights and claims whenever the sum is zero but some claim is not. With no such break, every claim is zero. Each weight is a product of distinct squeezed elements (ν_i τ_{i,j}, μ_i ρ_{i,j} η_M, δ_{M,i}), so the combination is affine in each element with the others fixed. At most one next element ends a combination that can still be nonzero, so k drawn elements cost k/|S|, also for several weights per squeeze and for nested products. squeezeBad charges each element that one value.

What the composed theorem covers

V3Endpoint.sound is the end-to-end statement for one circuit and one instance. V3Batch.sound runs all three checks as snarkVM does, each once for the whole batch, and gives every instance Az ∘ Bz = Cz on its own R_i. V3Batch.sound_of_transcript runs the checks on the opened values, reads the challenges and weights off the transcript's squeezes, and proves the relation for the statement the transcript absorbs. V3Batch.adaptive_soundness_concrete bounds the oracle tapes on which an adaptive prover gets a false statement accepted by Q · b · |S|^(Q−1) of |S|^Q, with b computed from the SRS size D and the domain bounds.

How the Fiat–Shamir row is charged

The batch's bad sets depend on earlier challenges: β's residual on α and the ηs, γ's on α, β and the δs. Each oracle query carries the statement and the history, every message followed by the elements squeezed after it, and that history decodes uniquely. An extractor reads, from the messages before each squeeze, the polynomials and sums they carry, so each squeeze's bad set is a function of its own query and is charged per query. The charge b is computed: if every polynomial the prover commits to has degree below D and every domain is within |R|, |C|, |X|, |K|, the three batched residuals have degree at most max(2|R| − 2, D + |R| − 1), D + |C| + |X| − 2 and D + |K| − 1. What stays outside are named floors: the degree below D is the algebraic-prover restriction, the extractor is commitment binding, and identifying snarkVM's sponge, which absorbs only the messages, with this query encoding is part of Poseidon = RO.

Decomposing the soundness error

Marlin reports its AHP error as one fraction per verifier challenge: a residual degree over the size of the set the challenge is drawn from. Varuna V3 has the same three Schwartz–Zippel fractions, now for batched residuals, plus one fraction per combiner squeeze, which Marlin does not have. Compiling with Sonic-PC and Fiat–Shamir adds the opening-batch terms and the factor Q.

The interactive AHP, one term per squeeze

For a combiner squeeze the numerator is a degree in the weights, not in a challenge point. A lucky combination is a root of a polynomial in the free weights whose coefficients are the claim errors. Each claim gets its own monomial (the first weight of a family is 1, so the first claim gets the constant), so the polynomial is nonzero whenever some claim is wrong, and Schwartz–Zippel over the weights bounds the chance by its degree over |S|. The degree is the nesting depth. The exception is two claims sharing a monomial, which is what V2's η_A = 1 did to the mask sum and the A claim.

Rows with a dot exist only because of batching. The 2, 3 and 1 are degrees in the weights, this canvas's multivariate Schwartz–Zippel count. Lean proves k / |S| for a squeeze of k drawn elements, one bad value per element: for the δs of n circuits that is 3n − 1, against |S| = 2²⁵² still far below the other terms. Selectors lift each circuit's residual to the largest domain without raising the degrees above these bounds. Marlin and the spec divide by |𝔽 ∖ H|. snarkVM rejects α ∈ R, β ∈ C and γ ∈ K outright, so a root inside the domain is never a break and |S| is a valid denominator. The exclusion costs completeness, about (|R| + |C| + |K|) / |S|, not soundness.

What bounds the degrees

Each numerator depends on the degrees of polynomials the prover commits to. The verifier enforces a degree bound only on g1 and the gM,i. Every other polynomial is limited by the SRS alone: an algebraic prover can use any of its D = 2²⁸ powers. The spec's 2|R| and 2|C| are the honest prover's degrees, which snarkVM asserts only on the prover side.

|X| is the input domain: ẑ = x̂ + v_X ŵ, so deg ẑ ≤ |X| + deg ŵ. D is the same for every circuit, so a small circuit does not get smaller terms. Marlin's formula keeps a degree parameter; the spec's has none. Against |S| = 2²⁵², the extra D moves each term by at most 2⁻²²⁴, so no conclusion changes. Lean proves these for the whole batch, selector-lifted to the largest domains, with |R|, |C|, |X|, |K| the largest sizes. Its b is snarkVM's, |R||C|(αβ − α col − β row + row_col) with the committed row_col, so a and b are K-interpolants and the matrix bound is the D + |K| − 1 above.

The deployed proof, with illustrative numbers

Sonic-PC batches the openings in two levels. At each of the three points, every polynomial gets its own 168-bit challenge; across points, each point after the first gets a fresh randomizer. Both are flat combinations, so each costs one bad value over |S_PC| = 2¹⁶⁸. The opening batch is the largest term. Marlin's compiler batches openings too, but snarkVM's PC challenges are 168-bit while the AHP's are 252-bit.

Assumptions: |S| = 2²⁵² (AHP challenges are 252-bit), |S_PC| = 2¹⁶⁸, Q = 2⁶⁴ oracle queries, D = 2²⁸, and upper bounds on the domain sizes, |R|, |C| ≤ 2²⁷ and |K| ≤ 2²⁸. The × Q column applies fs_query_charge's Q · b / |S| term by term, as the security analysis does, and summing it is conservative. V3Batch.adaptive_soundness_concrete charges every squeeze, combiners included, at one b = max(d_R, d_L, d_M, 1) computed from D and these domain bounds: b = D + |K| − 1 ≈ 2²⁹, so its AHP bound after Fiat–Shamir is Q · b / |S| ≈ 2⁻¹⁵⁹, below the summed column. Not in the numbers: pairing hardness, which turns a wrong opening or a violated degree bound into a trapdoor break; the algebraic-adversary restriction; and Poseidon as a random oracle.
